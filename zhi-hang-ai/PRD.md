# 职航 AI - 产品需求文档

## 1. 项目目标

面向北京市高校联盟学生，提供“岗位理解 - 简历诊断 - 经历改写 - 面试追问 - 复盘沉淀”的连续求职反馈流程。核心目标不是生成一段更像样的文字，而是帮助用户理解岗位要求，并完成一次可解释、可确认的求职准备。

### 目标指标

| 指标 | 基线 | 目标 | 口径 |
|---|---:|---:|---|
| 简历诊断完成率 | 47% | 70%+ | 上传简历后完成首轮诊断 |
| 建议采纳率 | 38% | 55%+ | 用户接受并保存的建议 / 展示建议 |
| 建议有帮助率 | 72% | 85%+ | 五级评价中 4-5 分占比 |
| 事实错误率 | 8.1% | <3% | 抽样人工复核 |
| P95 首次响应 | 7.2s | <5s | 岗位解析接口 |

## 2. 用户与场景

### 目标用户

- **临近投递的学生**：有简历，但不知道如何针对具体岗位调整。
- **缺少反馈渠道的学生**：参加过项目，却无法判断经历是否能证明能力。
- **准备面试的学生**：担心被追问项目细节，缺少结构化复盘。

### 核心场景

用户准备投递一个产品实习岗位，上传简历和岗位描述。系统先提取岗位职责、能力关键词和优先级，再标注简历中缺失的证据。用户选择一条项目经历，系统给出 STAR 结构改写建议，解释每处修改与岗位要求的关系，最后根据用户确认后的内容生成面试追问。

## 3. 需求范围

### P0

1. 岗位解析：提取职责、硬性条件、能力关键词和优先级。
2. 简历诊断：将岗位要求与简历片段建立匹配关系。
3. 修改对比：原文、建议稿、修改理由并列展示。
4. 用户确认：接受、拒绝、编辑建议；禁止静默覆盖原文。
5. 事实保护：未提供的数字、公司、结果不得由模型补造。

### P1

1. STAR 经历改写。
2. 逐级面试追问。
3. 版本历史与复盘记录。
4. 建议反馈与错误举报。

## 4. 关键交互

### 岗位解析卡片

- 岗位目标：一句话概括岗位要解决的问题。
- 能力关键词：按“必须 / 重要 / 加分”分层。
- 证据要求：每个关键词对应简历中需要出现的事实证据。

### 简历诊断卡片

- 匹配：已有证据，建议调整表达。
- 缺口：岗位要求出现，但简历没有证据。
- 风险：表达模糊、数据缺失或可能被追问。

### 修改对比

每条建议包含：原文、建议版本、修改理由、对应岗位关键词、需要用户确认的信息。

## 5. 埋点方案

| 事件 | 关键属性 | 用途 |
|---|---|---|
| job_parse_success | job_id, keyword_count, latency | 岗位解析质量与耗时 |
| diagnosis_view | gap_count, risk_count | 诊断内容使用情况 |
| suggestion_accept | suggestion_type, source_span | 建议采纳率 |
| suggestion_edit | edit_distance, field | 用户对模型输出的修正 |
| interview_followup_start | project_id, depth | 追问功能使用情况 |
| feedback_submit | score, reason | 质量反馈与错误分析 |

## 6. 非功能要求

- 所有模型输出保留来源片段和版本号。
- 用户可删除简历和历史记录。
- P95 岗位解析响应小于 5 秒。
- 关键结果支持重试，但不得重复写入版本记录。

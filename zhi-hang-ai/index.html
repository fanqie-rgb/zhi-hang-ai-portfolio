01 / 问题背景

高校学生并不缺少“生成一段文字”的工具，真正缺少的是把岗位要求转化为行动建议的反馈机制。普通聊天式 AI 常见三个问题：建议泛化、依据不透明、用户不敢直接采用。

15 + 6
学生与招聘方访谈

学生需要可执行修改；招聘方关注证据是否可信。

47%
首轮简历诊断完成率

用户看到泛泛建议后无法判断下一步。

8.1%
事实错误率基线

模型可能补造数字、结果或岗位要求之外的信息。

项目判断

产品机会不是做一个更会写的聊天机器人，而是建立“岗位证据 - 简历表达 - 面试追问”的闭环。

02 / 用户研究与机会定义

核心用户场景

投递前 30 分钟
用户拿到岗位描述，不知道哪些要求最重要。
修改简历时
用户知道项目做过什么，但不会把过程写成岗位需要的证据。
面试前一天
用户担心被追问细节，却没有对项目经历做压力测试。

机会树

提升求职准备完成度

→ 先理解岗位：提取职责、能力关键词与优先级

→ 再诊断证据：标记匹配、缺口和表达风险

→ 最后形成行动：修改、确认、追问和复盘

需求优先级

P0 岗位解析P0 简历诊断P0 修改对比P0 事实保护P1 面试追问P1 版本复盘

03 / 产品策略

将“聊天式问答”改造成“结构化工作流”，让用户每一步都知道输入什么、得到什么、是否可信、下一步做什么。

岗位解析
→
简历诊断
→
建议对比
→
用户确认
→
面试追问
→
复盘沉淀

不让模型替用户做决定

建议必须显示来源片段、修改理由和待确认字段；用户可以接受、拒绝或手动编辑。

不让 AI 补造个人事实

未在简历中出现的数字、公司、项目结果统一标为“需要补充”，不能一键写入。

04 / PRD 关键设计

模块用户问题产品方案验收标准
岗位解析不知道哪些要求最重要职责、能力关键词按必须 / 重要 / 加分分层关键词可追溯至岗位原文
简历诊断不知道简历哪里不匹配按匹配、缺口、风险三类标记片段每条建议绑定来源片段
修改对比建议太泛，无法判断是否该改原文 / 建议稿 / 修改理由并列用户可接受、拒绝、编辑
事实保护担心 AI 编造经历数字、公司、时间和项目名来源校验校验失败时禁止一键采纳
面试追问不知道项目会被怎么追问按项目事实逐级生成追问追问必须来自已确认内容

关键埋点

job_parse_success(job_id, keyword_count, latency) diagnosis_view(gap_count, risk_count) suggestion_accept(suggestion_type, source_span) suggestion_edit(edit_distance, field) interview_followup_start(project_id, depth) feedback_submit(score, reason)

05 / 技术方案与 AI 设计

系统架构

Web / Mobile

↓ API Gateway：鉴权、限流、审计

↓ Workflow Orchestrator

├ Job Parser：岗位解析 + Schema 校验

├ Resume Segmenter：简历片段切分

├ Retrieval：岗位 taxonomy / 规则 / 示例

├ LLM Router：质量模型 / 快速模型 / 降级

├ Fact Guard：来源、数字、实体校验

└ Evaluation Logger：trace、延迟、token、反馈

结构化输出契约

{ "status": "gap", "source_span": "项目原文片段", "reason": "缺少结果证据", "suggestion": "补充影响范围或指标", "needs_confirmation": [ "用户数量", "转化率" ] }

结构化输出用于前端渲染、字段级事实校验和建议采纳率统计。

Prompt 分层

系统约束层

事实保护、隐私、拒答边界。

任务层

岗位解析、诊断、改写、追问独立模板。

证据层

只允许引用岗位原文和简历片段。

06 / 模型评测与实验结果

构建 120 组脱敏样本，覆盖产品、商业分析、运营、咨询和技术产品五类岗位；每组包含岗位描述、简历片段、标准关键词、可接受证据和不可编造信息。

方案关键词召回证据绑定事实错误P95 延迟
普通聊天式 Prompt78%61%8.1%4.3s
结构化 Prompt89%87%4.6%4.8s
结构化 + 来源校验93%96%2.7%5.1s

用户实验

24 名学生完成同一份产品实习岗位的简历优化任务，随机分为聊天式问答组和结构化工作流组。

简历完成率

47% → 76%

建议有帮助率

72% → 89%

关键取舍

结构化工作流让平均响应时间增加 0.8 秒，但显著提升完成率和信任度。因此优先保留来源校验，并通过岗位关键词缓存、并行诊断和模型路由优化 P95 延迟。

08 / 项目复盘

做对的事

把 AI 输出拆成可验证的结构化字段，让产品体验、模型评测和数据分析使用同一套语言。

把“事实保护”前置到产品流程，而不是等用户投诉后再补救。

下一步

增加岗位 taxonomy 的长期维护机制；引入用户确认过的高质量案例作为检索样本；继续优化多轮追问中的上下文管理和延迟。
